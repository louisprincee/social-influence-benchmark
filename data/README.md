# 团队共享数据

所有路径相对于团队仓库根目录。

| 目录 | 用途 | 是否提交 Git |
|---|---|---|
| manifests | 来源、下载链接、文件哈希、处理规则、节点数和边数 | 提交 |
| tools | 将原始数据处理成公共图和方法输入的工具 | 代码完成后提交 |
| raw | 原始下载数据 | 默认忽略 |
| processed | 处理后的本地图、节点映射及方法输入 | 默认忽略 |

各算法原生数据仍位于 methods/方法名 中。当前已迁移的 HIM 数据位于 methods/HIM/data，配置和传播参数位于 methods/HIM/configs；它们与本共享目录不同。

## 新数据集尚待三人共同确定

已有的开发示例是 [SNAP Email-Eu temporal Department 3](https://snap.stanford.edu/data/email-Eu-core-temporal.html)。此前保留所有 89 名观测用户，取前 180 天、保留至少两次事件的有向关系，得到 464 条边和 15 个孤立点；统计记录在 manifests 中。

这个示例尚不是三个方法都已接入的最终数据。HIM 当前按无向图学习，GBIM 还需要用户—信息结构，必须说明转换规则与信息损失，不能直接把文件名换掉就当作对齐。

## 确定数据后提交哪些说明

来源及获取日期、原文件 SHA-256、时间窗口和过滤条件、去重规则、图方向、孤立节点保留方式、原始编号到内部编号的映射规则，以及各方法具体的输入转换。

节点集合与节点映射必须保持一致；某个方法若不支持孤立节点，需要明确记录处理方式并使评估口径一致。
