## 3. 先做作者代码复现

作者 README 提供的主要入口是 WIC 和 WLT。先选择 Cora-ML，运行完整 HIM 和 HIM_MD 两种方法：

```bash
# WIC：完整 HIM
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python run.py \
  --diffusion_model WIC --seed_ratio 10 --method ASW \
  --num_instances 30 --epochs 200 --R 100

# WIC：去掉 ASW 的选点变体
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python run.py \
  --diffusion_model WIC --seed_ratio 10 --method MD \
  --num_instances 30 --epochs 200 --R 100

# WLT：完整 HIM
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python run.py \
  --diffusion_model WLT --seed_ratio 10 --method ASW \
  --num_instances 30 --epochs 200 --R 100

# WLT：MD 变体
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python run.py \
  --diffusion_model WLT --seed_ratio 10 --method MD \
  --num_instances 30 --epochs 200 --R 100
```

`--seed_ratio` 是百分比：`1 / 5 / 10` 对应 Cora-ML 的 `28 / 140 / 281` 个种子。`--R` 是每个训练轮次的 Monte Carlo 评估次数；`--num_instances` 是传播训练样本数。`--epochs 200` 表示最多200轮，作者默认的早停机制可能提前终止。

超参数在 `configs/HIM_WIC.yaml` 和 `configs/HIM_WLT.yaml`。Cora-ML 使用64维表示、5个负样本；WIC 学习率为 `1e-4`，WLT 为 `1e-5`。先保持作者配置，后面再做有记录的敏感性实验。

日志位置：`save/cora_ml/<时间>_HIM_<传播模型>_<种子比例>/run.log`。

原始入口会输出 `best results at epoch ...`，但**没有保留该最佳轮次的模型和种子集**。它是在训练过程中反复评估得到的最大值，不能直接作为独立测试的最终结论。

## 4. 固定随机种子，并保存可复查结果

下面可直接粘贴到已激活环境的终端。它调用作者入口，额外设置随机种子，并保存**最后执行轮次**的种子集、模型与独立评估结果。这里的最终评估不会参与训练期间的选轮次。

```bash
PYTHONHASHSEED=42 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python - <<'PY'
import random, sys, runpy, json, time
from pathlib import Path
import numpy as np
import torch

rng_seed = 42
random.seed(rng_seed)
np.random.seed(rng_seed)
torch.manual_seed(rng_seed)
torch.set_num_threads(4)
sys.argv = ['run.py', '--diffusion_model', 'WIC', '--seed_ratio', '10',
            '--method', 'ASW', '--num_instances', '30',
            '--epochs', '200', '--R', '100']
start = time.perf_counter()
r = runpy.run_path('run.py', run_name='__main__')
train_seconds = time.perf_counter() - start
assert len(r['diffusion_edges']) == 30, '训练缓存不是30条样本，请按第5节处理'
seeds = sorted(int(v) for v in r['seeds'])
out = Path(r['save_path'])
(out / 'seeds_last_epoch.json').write_text(json.dumps(seeds))
torch.save(r['model'].state_dict(), out / 'model_last_epoch.pt')

# 使用新的随机数流，评估固定的最后轮次种子集。
random.seed(rng_seed + 1000)
np.random.seed(rng_seed + 1000)
torch.manual_seed(rng_seed + 1000)
mean, std = r['evaluator'].spread_evaluation(seeds, num_rounds=1000)
report = {
    'dataset': r['data_name'], 'diffusion_model': r['args'].diffusion_model,
    'method': r['args'].method, 'training_seed': rng_seed,
    'evaluation_seed': rng_seed + 1000,
    'last_epoch': r['epoch'], 'seed_count': len(seeds),
    'evaluation_target': 'last_epoch_seed_set', 'evaluation_rounds': 1000,
    'mean_activated': float(mean), 'std_activated': float(std),
    'spread_ratio_percent': float(100 * mean / r['num_node']),
    'training_seconds': train_seconds,
}
(out / 'final_evaluation.json').write_text(json.dumps(report, indent=2))
print('Results:', out)
print(json.dumps(report, indent=2))
PY
```

改变 `sys.argv` 中的 `WIC/WLT`、`ASW/MD`、种子比例即可切换设置。用 `42, 43, 44, 45, 46` 作为五次训练的 `rng_seed`，并同步设置命令行的 `PYTHONHASHSEED`。这里可固定已生成的传播训练样本，测量训练随机性；若研究传播样本生成的随机性，需要另存不同的样本库及其生成种子。

报告应分别注明：跨训练重复的均值/标准差，以及一次固定种子集在多次传播模拟中的标准差。两者不是同一个统计量。CPU 墙钟时间也不能直接与论文 GPU 时间比较。

## 5. 缓存必须检查

作者缓存名称只有“数据集 + 传播模型 + 种子比例”，没有包含 `num_instances` 或生成随机种子。例如当前缓存：

```text
data/diffusion/cora_ml_WIC_10.0.pkl
data/diffusion/cora_ml_WLT_10.0.pkl
```

当前本机 `methods/HIM` 中的这两个文件已从原目录复制，包含**固定生成种子42、修正随机数问题后生成的30条传播样本**。对应 SHA-256 和样本边数已收录到团队仓库 `experiments/results/native/HIM/cascade_manifest.json`；其中的 `file` 字段相对于作者运行目录。这些训练缓存默认不提交 GitHub，其他电脑需要另行同步或生成并检查样本数，不能假定解压后就拥有相同的缓存。

换样本数量或生成种子时，先备份相应缓存，再重新生成。以 WIC、10% 为例：

```bash
mkdir -p local_checks/cache_backups
mv data/diffusion/cora_ml_WIC_10.0.pkl \
  "local_checks/cache_backups/cora_ml_WIC_10.0_$(date +%Y%m%d_%H%M%S).pkl"
```

随后用第4节设置随机种子的命令，把 `--epochs` 暂时改成 `0`，并**只执行到** `r = runpy.run_path(...)` 为止；这样仅准备传播缓存。再恢复200轮运行训练。生成缓存和加载已有缓存消耗的随机数不同，先准备缓存、再训练才能让重复实验使用一致的初始化流程。

保留 `configs/diffusion/*_probs.pkl`；这些文件定义了实际的传播参数，不是可以随意清理的训练缓存。

## 7. 与课程作业要求的对应关系

**当前完成的是环境和作者数据集上的流程验证。Cora-ML 上跑 HIM 与 MD 两个变体，仍不足以完成小组项目。**

当前分工为：刘同学负责 HIM，李同学负责 DeepSN，姜来同学负责 GBIM。三个作者仓库分别位于团队根目录下的 `methods/HIM`、`methods/DeepSN`、`methods/GBIM`，复现材料位于 `reproduction/<method>`。可以额外加入 Degree/Random、Greedy/CELF 作为检查基线，HIM_MD 用来检验 ASW 的作用。

DeepSN 原入口默认 SIS 且忽略命令行参数；GBIM 使用用户—信息种子对和 Multi-IC/Multi-LT。三种方法在统一任务、种子定义及传播模型之前，各自结果只保存在 `experiments/results/native/<method>`。对齐后重新评估的结果才进入 `experiments/results/benchmark`。

老师要求不少于三个算法在新的有趣数据集上比较，因此还需要小组统一确定和整理新数据集。仅复用论文五个数据集不能自动证明已经满足“新数据集”这一条。此前项目中整理的邮件网络可作为候选，最终图方向、过滤条件、规模和数据来源需统一记录；HIM 当前实现按无向结构学习，若使用有向通信图，应明确无向投影的依据及信息损失。

新数据接入至少包括：重编号并保存节点映射、生成 `data/<name>/<name>.G`、登记数据集、添加含 `sample_ratio` 的训练配置、生成对应传播参数和训练样本。作者概率生成器用 `IC/PLT` 名称分支，而入口使用 `WIC/WLT`，**自定义数据不能仅把文件名改成新数据集后直接运行**，接入时需处理这个不一致。此项本轮尚未实施。

统一实验时固定图、种子预算和真实评估模型，并记录各算法获得的信息。若额外加入的 Greedy/CELF 访问真实传播参数而 HIM 只读取传播历史，前者应标注为“已知参数参考”。共享实验配置、脚本和评估工具统一放在 `experiments/` 中，目前尚未实现。

建议课程实验表：`数据集 × WIC/WLT × 1%/5%/10% × 算法 × 5次训练重复`。记录独立传播覆盖率、训练时间、选点时间、总时间；控制训练样本数量和评估随机数。可写的分析包括传播效果与耗时权衡、ASW 与 MD 差异、种子预算变化，以及传播历史数量变化。结果好坏均应如实解释。

Milestone 可以先写真实的数据统计、数学模型、算法流程、环境差异、已经完成的运行验证及剩余计划。只有跑完的实验才能写作实验结果；英文综述围绕双曲表示、学习式影响力最大化及种子重叠处理展开。后续 LaTeX 版本使用用户指定的双栏排版，并保持 milestone 3–5页、个人综述不少于1000英文词及参考文献要求。

## 8. 本地修改与证据

保留了作者学习、选点和概率模型实现；修改了两个影响使用/复现的问题：

1. `run.py`：为 `--seed_ratio` 增加 `type=float`，修复 README 命令导致的 `TypeError`。
2. `modules/diffusion/DiffusionModel.py`：仅在显式传入种子时调用 `np.random.seed(seed)`，避免默认 `None` 破坏调用方的固定随机数流。

这两项修正保存为团队根目录下的 `reproduction/HIM/reproduction.patch`。Mac 依赖文件和环境锁定文件在同一目录。应用补丁后，可用 `git -C methods/HIM diff`（从团队根目录）检查作者代码修改。

早期测试记录已同步到本机 `methods/HIM/local_checks/`，原目录仍有备份。它们默认不提交 GitHub。这些是5轮训练、30条传播样本、每轮10次评估的运行验证，不是完整论文实验或最终排名。

已验证第4节的保存/独立评估流程。早期5轮测试得到覆盖率34.3923%，完整预算的后续运行在第54轮早停，其最后轮次种子集独立1,000次模拟的覆盖率为37.619466%。团队收录的种子集、结果和审计证据位于 `experiments/results/native/HIM`。完整日志与模型权重已同步到本机 `methods/HIM/save/cora_ml/1009_150839_HIM_WIC_10.0/`，原目录有备份，但它们默认不提交 GitHub。不能据此声称已经完成与其他算法的公平比较。

论文与代码有需要报告的设置差异：例如论文 WIC 段落给出 `[0,0.2]`，仓库 Cora-ML 的实际概率文件范围为约 `[0.1,0.2]`；论文描述 WLT 固定参数，而代码每次模拟重新采样节点阈值。因此应明确报告“使用哪个版本的论文、哪个提交的代码和实际概率文件”，不能宣称这些命令已经逐项复现论文所有表格。[论文实验设置](https://arxiv.org/html/2502.13571v2#S5.SS1)
