# 三人协作与提交指南

所有命令的起点都是 social-influence-benchmark 仓库根目录。

## 每个人从哪里开始

1. 用 --recurse-submodules 下载团队仓库。
2. 打开 reproduction/自己方法/README.md，按当前状态准备独立环境。
3. 在 methods/自己方法 运行作者程序。GBIM 的实际运行目录是 methods/GBIM/GBIM。
4. 保留每次实验的参数、随机种子、日志、模型和真实种子集。
5. 将小型成果放入 experiments/results/native/自己方法/运行编号，课程报告放 reports/自己方法。

HIM 已有成果，刘同学可以继续现有实验；DeepSN 与 GBIM 尚需分别验证环境与训练。三人可以独立推进，公共数据与评估的决定再共同同步。

## 分支与文件分工

建议使用 HIM/任务名、DeepSN/任务名、GBIM/任务名 或 experiments/任务名 分支。首次提交建立 main 后再开始分支工作。

```bash
git switch -c HIM/next-experiment
git status --short
git add reproduction/HIM experiments/results/native/HIM reports/HIM
git commit -m "Record HIM experiment"
git push -u origin HIM/next-experiment
```

上面的任务名和说明是示例；按各自方法替换。向 main 提交 PR，避免三人同时直接修改同一个公共配置。修改公共数据过滤规则和评估模型之前先同步，否则已有结果可能不再可比。

## 子模块代码修改必须单独保存

主仓库的 git add methods/HIM 不会把子模块里未提交的 run.py 修改变成主仓库文件。当前 HIM 的两项修改已经保存在补丁中；子模块显示 modified 是预期状态。

修改完指定代码后，从团队根目录导出补丁：

```bash
git -C methods/HIM diff -- run.py modules/diffusion/DiffusionModel.py > reproduction/HIM/reproduction.patch
```

其他方法对实际修改的文件导出各自补丁。补丁以固定作者提交为基准，组员在干净作者代码上应用一次。不要在子模块里直接推送到作者仓库；本课程阶段用补丁共享更清楚。

## 数据、模型与 GitHub

GitHub 默认保存源代码版本、补丁、环境记录、配置、种子 JSON、指标和报告。原始数据、处理数据、传播缓存、模型权重和虚拟环境默认不提交。

这不表示它们没有保存：HIM 本机完整原实验在 methods/HIM 中，文件清单在 experiments/results/native/HIM/artifact_manifest.json。其他成员需要同一模型或缓存时，另外同步文件并核对哈希；不能只依赖 GitHub 下载来获取被忽略的文件。

忽略规则有两层：团队根目录规则不作用于子模块内部，子模块需使用自己的忽略规则。本机 HIM 的 local_checks 已通过本地 Git 排除规则忽略，不会误入作者代码补丁。

## 每次提交前检查

- 方法名称、节点映射、种子预算和随机种子写清楚。
- 种子集是真实输出，参数与日志可追溯。
- 结果是原协议 native 还是统一协议 benchmark 标记清楚。
- 没有把不同传播目标或未完成的适配当作可比结果。
- 新增环境、数据与权重没有误入暂存区。
- 三人最终统一图、种子定义、传播参数和独立评估设置后再生成比较表。

个人综述参考文献另行核对交集不超过3篇；方法选定不代表参考文献交集已经合规。
